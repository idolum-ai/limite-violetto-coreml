# Isolated group-0 product variant: build review

I reviewed the planned 05e ablation in `evidence/05d-decode/next-experiment.json`, the qualified `paired_product.product`, converter injection points, and the group graph. No conversion, native load, or inference was performed.

**Recommended build:** make a side-by-side copy of only the qualified group-0 `.mlpackage` and alter its MIL program in the copied `model.mlmodel`. In each of the four value-product concatenations, replace the 16 inputs with 16 references to the *existing first two-row matmul output*. This preserves concatenation arity, 32-row output geometry, downstream slice, public input/output and eight state declarations. After a complete def-use check, remove only the 15 now-unreferenced pure matmul ops per layer (60 total). Leave their dead slice/constant ancestors in place for this first variant; deleting them adds graph changes without being necessary to remove the products. Require the source spec inventory to show 68→8 matmuls, four concat rewires, no other changed surviving op bytes, unchanged model description/state schema, and unchanged weight blob bytes. Preserve the original package and record the copy's own identity.

This narrow surgery is preferable here to a process-local product monkeypatch and retrace. The frozen converter traces group inputs at length 3 and declares a 1–32 query range; a product returning only the first pair cannot satisfy that trace at length 3. Tracing length 1 or changing the input range would also change shape specialization, introducing a second cause of any measured latency difference against the qualified group-0 package. Editing the already qualified MIL graph keeps its other traced arithmetic and interface fixed. Raw protobuf editing still requires strict structural checks: each removed matmul output must have no remaining consumer anywhere in its block, nested blocks, function outputs, or state updates; preserve operation order, names of surviving values, and external weight references. Re-parse and compile the copied package before any native call.

The resulting package deliberately advertises the original broad input interface but is **valid for this experiment only when the harness enforces one real query, one position ≥32 and <2048, and the captured group-0 input/state schema before native prediction**. Its repeated first pair would return wrong values for larger real-query counts. It must never replace the qualified group or enter prefill/generation routing. Use the qualified baseline package for comparison and fresh, independently restored states for every arm. Exact `y`, `tap23_out`, and all eight post-call state arrays against the sealed position-32 capture are prerequisites; repeat on independent warm inputs before a broader claim. A compiler may schedule the surviving matmul differently even though its source op bytes are unchanged, so fidelity and ABBA latency are empirical gates, not implications of the graph edit.
