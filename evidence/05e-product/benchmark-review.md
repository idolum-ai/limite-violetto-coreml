# Prelaunch static review of the 05e product benchmark

No launch-blocking correctness flaw found in `scripts/build_decode_product.py` or `scripts/benchmark_decode_product.py` as inspected before the p512 capture completed. No inference, compilation, or full-tree hashing was run for this review.

The completed `repeat-first-2` build record reports a sealed source candidate, only `model.mlmodel` changed in the copied group-0 package, four 16-input concats rewired to repeat their original first product, 60 unused matmuls removed (68→8), 42,434 other surviving operations byte-identical, and non-operation metadata unchanged. The copied variant compiled successfully. This supports the intended graph manipulation, subject to the benchmark's separate native exactness gate.

The benchmark rejects non-single-query, non-warm positions before native calls; verifies the sealed baseline compiled identity and the build/fixture digests; constructs both models under CPU_ONLY after installing the prediction guard; restores a new state for **every** call; times only `CompiledMLModel.predict`; then checks both outputs and all eight post-call states exactly. Twelve correctness calls precede any benchmark observation. Its 24 warmup calls are excluded. Three blocks rotate prefix order; four ABBA cycles per prefix/block produce 144 timed observations, with restoration and exact checks outside each timer. The predeclared decision requires at least 10% median group-call reduction in each of nine block/prefix cells. This is a local group-0, one-query result, never a whole-model speedup or integration qualification.

Two nonblocking provenance/interpretation improvements are recommended. First, while each capture results file and NPZ is digest-pinned, the benchmark should explicitly compare each capture's `loader_provenance` and `runtime_provenance` with the current sealed baseline/milestone, and require `status == "completed"`; baseline exact replay already provides a strong practical cross-check. Second, record the prediction-guard installed flag and expected call counts as an assertion, and label the reported elapsed time as a synchronous group prediction including Core ML bridge/output conversion. Fresh-state writes before each timed call may change host caches; ABBA and rotated prefix order reduce but do not remove that bias. A native compiler can still change scheduling of the surviving matmul despite its unchanged MIL op bytes, so exactness plus raw paired timings remain decisive.

Root addressed both recommendations before launch: capture status and loader/runtime identities must match qualification; guard counts must equal 180 stateful calls and 180 GIL releases, with zero stateless calls. The result explicitly labels the synchronous bridge-inclusive prediction boundary.
