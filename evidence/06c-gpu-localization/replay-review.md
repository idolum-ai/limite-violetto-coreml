# Static review of `localize_gpu_drift.py`

Review was read-only. No model was loaded and no inference was run. This script deliberately traces only prompt 0 through groups 0–4; it does not execute a new head/score comparison or proceed past the first measured hidden-threshold crossing. It independently checks the portable reference at embedding plus `layer_3`, `layer_7`, `layer_11`, `layer_15`, and `layer_19`, and requires the six GPU metric dictionaries to reproduce the completed short screen. That is consistent with the stated localization scope; it does not reproduce prompt 0's failed score metric.

The factorial design is implemented coherently. Each policy has its own model states and two-chunk trajectory. Each 44-token prompt is embedded as chunks 32 and 12, positions are absolute, taps reset from each chunk's embedding, `tap23` advances each group, and `tap12` is refreshed after group 2. Each group's complete input mapping, all source-declared before/after states, and outputs are retained for both own trajectories. The cold chunk deduplicates identical all-zero cache sources (two input trajectories × two policies = four calls per group); the warm chunk runs all eight input-source × state-source × compute-policy cells. Each fresh replay state is read back after restoration before prediction. Same-cell CPU/GPU contrasts hold input and cache fixed, and own-policy diagonal replays must exactly match the captured trajectory. For the five groups this yields 20 own-trajectory calls plus 60 fresh factorial replays, 80 state calls total, and four embedding/plain calls; the guard assertion expects 84 releases. The script checks the CPU checkpoints exactly against the reference and checks each GPU metric against its prior full-screen metric at the configured tight tolerances.

Source/cache/runtime pins are checked before and after the native calls. The compiled identity verifier also revalidates the source package; `qualified_context()` checks the pinned runtime and guard/source cohort; prediction guard counters are required to begin at zero and finish at the exact planned totals. The script snapshots itself and its protocol, rechecks their hashes at the end, saves NPZ hashes and shapes as progress proceeds, and labels device placement unverified. The comparison helper reports array exactness and finite-value counts. The current script does not explicitly assert that each group package exposes exactly eight state names; the verified candidate identity pins the schema, but an explicit eight-name check would make the stated all-eight-state coverage clearer.

Two prelaunch changes are recommended before treating the capture set as fully replayable. First, `archive()` writes the trajectory input dictionary before `predict()` adds `norm_divisor`. The compiled model receives that extra input, but the saved `inputs.npz` does not. Include the effective payload in the archive, or separately record and hash the injected value and dtype/shape (`[1280.]`, float32) for every call. Second, final `passed: true` means the localization procedure completed, but could be mistaken for a fidelity pass. Prefer an explicit completion field and a separate exactness/fidelity status (`diagnostic_complete`, `not_qualified` / `not_exact`). The current prose says this is diagnostic, yet a boolean named `passed` remains ambiguous. Likewise `disposed=60` records Python references deleted and the loop count; without cleanup-guard lifecycle stats it does not independently prove native state destruction. Report that as replay states released by the runner, not as a separate native cleanup qualification.

Interpretation stays appropriately bounded: a first threshold crossing at group 4 is a measured location in this prompt's captures, not the earliest bitwise difference or a proven cause. The previous group 0 probe used different inputs and starting states. Factorial differences can describe sensitivity to the saved input-source and cache-source factors, but should not be presented as causal attribution beyond those tested cells. `CPU_AND_GPU` remains a compute policy; actual device placement is unverified.
