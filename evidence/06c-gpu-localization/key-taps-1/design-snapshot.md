# Group-0 first-key instrumentation design

This is a read-only design for a side-by-side clone of the sealed candidate-6 `0.mlpackage`. The source package's `model.mlmodel` is recorded in `evidence/04d-cpu/full-candidate-6/package-identity.json` with SHA-256 `6cdf80c050b8076357009efe870618afc1210fa0ddd07d06df6749caefcf6950`. I inspected the `CoreML8` main block and `coreml_port/graphs.py`; no package was changed, compiled, or predicted for this note.

The first layer's key path, in original MIL operation order, is:

| Checkpoint | Operation | Shape and role |
| --- | --- | --- |
| `x_3` | 508 `mul` | FP32 `[1,Q,1280]`; `norm(x)` before its BF16-emulating round. |
| `x_5` | 535 `mul` | FP32 `[1,Q,1280]`; rounded normalized input to Q/K/V projection. |
| `x_9` | 1141 `add` | FP32 `[1,Q,256]`; raw key linear reduction before its round. |
| `value_5` | 1169 `reshape` | FP32 `[1,Q,2,128]`; rounded key projection. |
| `x_19` | 1566 `mul` | FP32 `[1,Q,2,128]`; key-head normalization before its round. |
| `k_7` | 1592 `mul` | FP32 `[1,Q,2,128]`; rounded normalized key. |
| `x_31` | 1740 `add` | FP32 `[1,Q,2,128]`; RoPE sum before its final round. |
| `k_9` | 1766 `mul` | FP32 `[1,Q,2,128]`; rounded rotated key. |

RoPE factors are `cos_1` at 44 and `sin_1` at 50. `k_9` is the `update` input to key-cache `slice_update` at 1790; `cast_46` at 1792 converts the updated full cache to FP16 and `write_state` at 1793 stores `inner_k_cache_0`. The source graph's ordinary outputs are `y` and `tap23_out`, and it has eight state inputs for the four layer K/V caches. These MIL names/indices belong only to this exact sealed package, so a builder must assert them and their producer/input relationships before cloning.

For a minimal first pass, append **four existing SSA values**—`x_5`, `value_5`, `k_7`, `k_9`—to the copied block's output list and append matching FP32 multi-array entries to the copied model description output list. Keep `y` and `tap23_out` first and unchanged. Do not add or rewrite an arithmetic operation, input, state descriptor, weight, or original output. Assert every original operation is byte-identical, the source package remains sealed, only the copied spec changes, and the variant package/compiled artifact has a new identity. The four checkpoints separate input normalization, key projection, key normalization, and RoPE/final rounding at BF16-representable stage boundaries. If the earliest mismatch lies between two checkpoints, make a *second* fresh clone with only the adjacent pre-round value (`x_3`, `x_9`, `x_19`, or `x_31`) to narrow it. If `k_9` is equal while the cache differs, inspect the `slice_update`/FP16 cast/write path instead.

Adding outputs can alter Core ML optimization or scheduling even though MIL arithmetic is unchanged. Before interpreting any checkpoint, run the **original and instrumented clones on identical saved inputs with independent fresh copies of all eight incoming states** under both `CPU_ONLY` and `CPU_AND_GPU`. For each call/chunk, require exact equality of original `y` and `tap23_out` and all eight post-call state arrays between clone and original **within the same compute policy**, including the active key-cache window. Run this control for the 44-token failed prompt as 32+12 chunks and the shared-input/state replay cases. If an endpoint or state differs, reject that instrumentation variant and do not localize from its intermediate outputs. Save inputs, pre/post states, original/variant outputs, intermediate arrays, source/variant identities, compute-policy labels, script hashes, and the earliest differing element coordinates. Then compare CPU versus GPU-policy checkpoint arrays only after the within-policy controls pass. `CPU_AND_GPU` is a policy label; these results alone do not prove an operation executed on the GPU. Exact endpoint/state controls reduce—but cannot eliminate—the possibility that exposing an intermediate changed internal optimization while leaving observed outputs unchanged.

The isolated `scripts/build_gpu_key_taps.py` builder implements only this four-output first pass. It pins the sealed source identity and exact operation positions/types/dependency path, rejects an occupied attempt, writes a copied package under `artifacts/06c-gpu-localization/<attempt>`, and records source/variant/optional compiled inventories under the matching evidence attempt. For each tap, the model-description output is FP32 with default query length 3 and shape range 1–32, matching the source input's dynamic query range and the MIL value's fixed dimensions. It asserts a deterministic digest and byte equality for every original operation, equal spec bytes after removing only the two appended output lists, unchanged package files apart from `model.mlmodel`, and source identity stability. `--compile` is optional and installs the prediction guard before compilation. A read-only in-memory application of the four-output edit passed structural, type, and serialization checks; native compilation and endpoint/state controls remain to be run by the root harness.
