# Conditional pipeline benchmark static review

Reviewed `scripts/benchmark_conditional_pipeline.py` SHA-256 `8e1e1288205dfaeef2420dc02841139c09478902700b599608b9fe1d95db0485` and `benchmark-protocol.json` SHA-256 `29191d62acfe096568c979c44426fd6e4ae11f1a607036dacb03d4a934a92d1b`. The script checks its own hash, the qualification helper hash, and the fixture hash against the protocol; all three currently match. No native inference or benchmark was run for this review.

No launch blocker found. The parent binds the passing candidate milestone and its gate-result hashes, qualified source cohort, source and compiled identities, and absolute model/cache selection. Each of eight sequential fresh subprocesses repeats the cohort check, loads one CPU_ONLY compiled pipeline, and checks loaded identities. The schedule is ABBA in both rounds, with prefix order 32/128/512 then 512/128/32. Each worker uses one warmup request and three measured requests, with one prefill plus three teacher-forced decode forwards per request. The 719-token pinned stream covers the largest prefix plus three decode inputs. Score arrays for all 12 measured sites per worker are compared with the first baseline worker; any mismatch prevents a performance decision. Requests close in `finally`; each worker requires the expected plain/state/GIL guard counts (50/408/458). The 408 state calls correspond to 12 group calls across 34 source chunks or decode steps (4 warmup + 4 at prefix 32 + 7 at prefix 128 + 19 at prefix 512).

Only synchronous `Pipeline.forward` is timed. This includes existing 32-token prefill chunking and the pipeline's ordinary host work; model load, identity checks, request creation/disposal, telemetry, score copying/saving, and equality checks are outside the timer. The decision requires a median B/A ratio at most 0.90 at each decode prefix and pooled, and at most 1.10 for prefill at each prefix. Per-round reductions and host telemetry are retained. Two rounds are a bounded local comparison and do not control OS caching or scheduling.

Minor reporting precision: the script calls `np.array_equal` results “bitwise” in one error string. That is exact value/shape equality, but does not distinguish signed zeros or equal values represented by different dtypes. The final report should say value-exact unless raw bytes are also checked. This does not affect the timing gate or ordinary score parity interpretation.
