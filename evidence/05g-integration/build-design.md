# Conditional tiny-score integration design

The sealed candidate-6 group computes ordinary scores and the tiny-prefix score tree, then selects the latter when prepared query rows are below 16. The 05f warm-only ablation proved that the tiny branch can be omitted for a single warm query, but its package is not valid as a general replacement. This builder instead changes each of four final score `select` operations to a Core ML `cond` with the same existing scalar `rows < 16` predicate. The true block evaluates the original tiny tree; the false block returns the already computed ordinary score. The one package retains one state interface.

For each group, the builder walks the original main block, treating earlier final selects as opaque when tracing later branches. It partitions live operations into a parent graph, four disjoint short-only closures, and any shared ancestors retained in the parent. The group-0 inspection found 10,009 short-only operations: 10,004 in four closures of 2,501 and five shared constants retained outside. All moved operations preserve their original protobuf bytes. No state operation, matmul, weight, input, output, or non-operation spec metadata moves or changes. Each true block ends with a new `identity` whose declared output type is copied from the original score select, refining the short concat's inferred unknown last dimension to the full score's fixed 2048. The concat is 16 active columns plus 2032 masked columns. Each false block has a new local `identity` of the parent ordinary score. Both identities leave score values unchanged and give each block a locally produced output.

Attempt `conditional-group0-1` compiled, but native load failed because an empty false block returned an outer `full_scores_1` value directly: E5RT reported it was not produced inside that block. The builder now emits the false-block local identity and explicitly checks both branch outputs are local. The failed attempt is preserved; the fix requires a fresh attempt.

The first batch build then exposed a group-6 template assumption: that qualified group has no original `identity` operation. The builder now uses an identity from the same sealed source cohort's group 0 as a protobuf template only in groups without one. It still replaces its input, output, type, and name per branch. A read-only, full in-memory transformation of all 12 groups passed selector partitioning, parent and branch SSA, original operation byte preservation, non-operation metadata equality, and unchanged state/matmul counts. This check did not compile or run the models.

`scripts/build_conditional_scores.py --group G --attempt NAME --compile` first verifies the sealed source identity, rejects occupied attempt paths, copies only group `G`, rewrites its spec, and records source/variant file digests and structural assertions in `evidence/05g-integration/NAME/results.json`. Artifacts go under `artifacts/05g-integration/NAME`. It compiles only when `--compile` is given. Compilation and native replay remain separate qualification gates; static graph checks alone cannot prove Core ML's conditional runtime scheduling or shape handling. The initial gate is one isolated group-0 build, compile, and exact replay for cold, tiny, and warm paths. Only then should all groups be built and full gates run.
