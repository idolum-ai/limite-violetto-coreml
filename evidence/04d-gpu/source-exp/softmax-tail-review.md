# Softmax key-count tail review

The fixed 2048-slot ordered softmax has the same four-lane sum order as the pinned Torch CPU FP32 softmax for **4 through 2048 real keys**, including nonmultiples of four. The reference slices its cache to the current end position ([portable/model.py](../../../portable/model.py), lines 189–199), whereas the Core ML graph masks unused slots to negative infinity ([coreml_port/graphs.py](../../../coreml_port/graphs.py), lines 71–79). Those masked slots contribute positive zero after exponential.

The pinned CPU FP32 last-dimension kernel calls `vec::reduce_all` for the exponential sum ([SoftMaxKernel.cpp](../../../sources/torch-2.7-linear/SoftMaxKernel.cpp), lines 113–143). For at least four elements, `reduce_all` accumulates complete four-element vectors in four lanes, then handles a one-to-three-element tail through a partial load and `Vec::set`, retaining the untouched accumulator lanes ([functional_base.h](../../../sources/torch-2.7-linear/functional_base.h), lines 136–150). The NEON partial load zero-fills missing lanes ([vec128_float_neon.h](../../../sources/torch-2.7-linear/vec128_float_neon.h), lines 163–175). Adding the graph's extra zeros in each lane is exact for nonnegative exponentials, and the final NEON fold is the same. Thus a scalar tail in the reduced-precision overload (SoftMaxKernel.cpp lines 182–195) does not apply here: attention scores are FP32.

There is a **three-key short-context exception**. If the real dimension is less than four, `reduce_all` calls the scalar slow path ([functional_base.h](../../../sources/torch-2.7-linear/functional_base.h), lines 11–27 and 136–140). At three keys, that path sums `(a+b)+c`, while the 2048-slot ordered graph's four-lane fold sums `(a+c)+b`; these can differ by one FP32 ULP. For example, with positive exponentials `a=1`, `b=0.36899313`, `c=0.51139003`, float32 gives 1.8803833 versus 1.8803831. One- and two-key sums collapse to the same order. The existing tiny three-token checkpoint was exact at its measured output, but it does not establish bitwise identity of every raw softmax weight.

This review is source-level and uses no model inference. It identifies no additional softmax tail-order hazard for long contexts up to the current 2048-slot capacity. Other numerical operations or contexts beyond that capacity remain outside this conclusion.
