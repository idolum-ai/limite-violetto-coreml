# Source-ordered XSA correction — shard 0

The prior all-site ordered RMS shard was exact for CPU decoding but had a small 32-token prefill difference. Its first diagnostic rounding mismatch was layer-2 XSA correction `round_82`, immediately after an exact weighted-value output.

I captured the same Torch layer-2 weighted attention output, value tensor, and alpha that feed this site. On those values, `ordered_sum(y*vn)` exactly matches Torch's native dot. The native `F.normalize(v)` uses a different norm2 reduction order from RMS `ordered_sum`: one four-lane square accumulator advances through 128 values, followed by the linear lane fold `(((a0+a1)+a2)+a3)`. This expression and direct division reproduce Torch's norm and normalized values exactly on the capture. A generic RMS sum/sqrt substitution does not. [Captured operands and comparisons](capture.json), [norm-order controls](norm-orders.json).

The isolated Core ML source-order expression matches Torch exactly at every exposed stage—norm, normalized values, product, dot, correction, and BF16-rounded correction—under CPU_ONLY and CPU_AND_GPU. The original isolated expression has small raw differences, though its rounded correction is exact there; the composed diagnostic is therefore the decisive localization. [Original operator probe](operators.json), [source-order operator probe](ordered.json).

An uninstrumented four-layer shard replaces XSA normalization and dot in all four layers, while retaining ordered linear, ordered softmax, and all-site ordered RMS norm. Its Torch outputs match the original ordered Torch shard exactly. **CPU_ONLY Core ML matches the original Torch shard exactly** on the 32-token prefill, the next one-token decode, and the following three-token decode: maximum absolute error and relative RMSE are zero for all three. GPU-permitted execution still differs, with relative RMSE `0.001395020`, `0.008523712`, and `0.008401641`; the separately identified key midpoint remains unfixed in this package. [Uninstrumented shard evidence and package hashes](shard0.json).

The experimental package is `artifacts/04d-gpu/xsa/shard0.mlpackage` and takes an extra runtime `divisor1280` scalar. Reusable XSA arithmetic is in [`gpu_xsa_math.py`](../../../scripts/gpu_xsa_math.py); the bounded shard wrapper is [`gpu_xsa_shard.py`](../../../scripts/gpu_xsa_shard.py). Source hashes in `shard0.json` pin `graphs.py`, `ordered_linear.py`, `ordered_attention.py`, `ordered_norm.py`, the wrapper, and XSA math. This one-shard result does not establish full-model score, cache/window, or original NVIDIA-runtime fidelity. The candidate must pass the complete unchanged local gates before selection.
