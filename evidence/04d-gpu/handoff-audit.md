## Handoff gaps found

1. The [candidate-4 command block](../04d-cpu/commands.md) uses the already occupied `--attempt full-candidate-4`, although [the builder](../../scripts/build_cpu_candidate.py) creates both output directories with `exist_ok=False`. Copying the block verbatim now fails before conversion. Show a fresh example attempt name and consistently substitute its model, identity-manifest, and evidence paths in every subsequent command; keep the original historical command as a labeled record if needed.
2. The candidate-4 command block omits the required guard build prerequisite. On a clean environment, [runtime construction](../../coreml_port/runtime.py) calls `cleanup_guard.install()`, which refuses to run without `artifacts/04b-reliability/cleanup_guard.dylib`. The [README](../../README.md) gives `.venv/bin/python scripts/build_cleanup_guard.py`, but a self-contained candidate rerun recipe should put that command after environment installation and before Core ML validation. It should also identify the required `xcrun`/Xcode command-line tools and the bridge hash pin.
3. The README's `scripts/verify_sources.py` command verifies the earlier model/runtime source set, **not** the newly retained PyTorch/SLEEF/Core ML bridge snapshots. Their saved JSON hashes currently match, but there is no documented single command that checks them during a fresh handoff. Add a small read-only verifier or explicit hash-check commands for the [initial Torch file index](../04c-precision/torch-2.7-linear-hashes.json) plus the [newer arithmetic kernel index](../04d-cpu/arithmetic-source-identity.json), [SLEEF file index](../04d-cpu/sleef-source-identity.json), and [bridge file index](../04b-reliability/coremltools-9.0-bridge-hashes.json), and name the pinned upstream revisions in the rerun instructions.

No missing retained upstream license was found for the inspected arithmetic, exponential, or bridge sources. The three fixes do not require changing the sealed candidate packages or numerical thresholds.

## Fixes and verification

The [new verifier](../../scripts/verify_arithmetic_sources.py) checks the initial and newer Torch inventories, the SLEEF inventory and parent submodule revision, the retained Core ML bridge sources and installed binary pin, cleanup-guard source/binary hashes, locked Torch/Core ML Tools versions, and source notices. It prints JSON without writing by default; `--output` creates one new JSON file and rejects an occupied path. The recorded [verification](arithmetic-source-verification.json) passed **42/42 checks**. A prior 40-check inventory is retained as [initial evidence](arithmetic-source-verification-initial.json); the final verifier adds the guard C source and dylib checks. An attempted write to the occupied final path exited 2 without overwriting it.

The [candidate-4 commands](../04d-cpu/commands.md) now label the original paths as historical and provide a fresh `full-candidate-4-rerun1` example with consistent model/evidence paths. They also state the CPython 3.12.9/macOS arm64 and Xcode prerequisites, conditionally build the missing guard, and invoke the source verifier before conversion. The pinned candidate-4 packages and acceptance criteria remain unchanged.
