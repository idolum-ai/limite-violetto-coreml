# Review of a one-query group-0 product ablation

**Defensible as an isolated first experiment, with no performance or fidelity conclusion yet.** The qualified `paired_product.product` pads attention weights to 32 query rows, performs 16 separate two-row products, concatenates them, then slices to the real query count. For exactly one real query at absolute position at least 32, only the first row of the first two-row product is returned. A decode-only group-0 variant that retains that first two-row matmul, query padding, score path, weights, and native guards while omitting products for rows 2–31 tests a specific graph-work hypothesis. It does not require a runtime change or adoption.

The profile locates about 98% of measured forward time in the 12 backbone group predictions, but it does not resolve attention-value products within a group. The 16 products are visible in the source graph; Core ML may fuse, elide, or schedule them differently. Likewise, deleting 15 products could change the *remaining* matmul's compiled kernel or precision behavior despite unchanged logical operands. Treat the new MIL operator-count/shape diff as a manipulation check and the paired wall-time measurement as the result; neither alone proves internal work or speedup. Any observed group-0 change is local to that package and cannot be scaled to all groups without further experiments.

Scope and validation before interpreting timing:

1. Compile to a separate package/cache with source and weight identity recorded. Constrain its public input to **one real query**, at **warm absolute position ≥32**. Keep the sealed 14-package baseline and prefill path untouched. Verify the variant changes only the value-product branch plus compiler consequences, with the first product still shaped as two query rows by 2,048 keys and 128 value channels. Record the MIL/spec diff and compiled identity.
2. Replay the captured group-0 position-32 input with a **fresh state** initialized from the captured `state-before` bytes for each baseline and variant call. Compare both output tensors (`y`, `tap23_out`) and all eight post-call KV states bitwise to the qualified baseline capture, not only final scores. The existing baseline capture already passed two fresh-state exact replays. Verify guarded execution and state disposal. If exactness fails, localize the first divergent output/state before any timing claim.
3. Repeat correctness on at least one independently captured warm position/input and, if a latency claim is sought, across the 32/128/512 prefix conditions. Use separate equivalent states for every arm; never share or continue one native state object across baseline and variant. Alternate control/variant order, exclude initial shape warmup, time the same group-0 prediction boundary, and retain raw paired observations plus host conditions. Compare only the one-query warm-decode domain. Do not infer prefill, short-prefix, whole-model, or token-generation effects from this ablation.

No model conversion, inference, or source edits were performed for this review.
